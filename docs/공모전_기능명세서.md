## 1. MVP 구현 범위

예선 MVP는 **손실 복기(분석단)와 사전 경고(예측단)의 전 구간이 하나의 웹 서비스로 연결되어 동작하는 상태**까지 구현했다.

**구현된 범위**

1. **데이터 파이프라인** — KOSPI 798종목 1년치 1분봉(5,467만 행)을 수집·정제하고, 체결 내역을 매수→매도 사이클로 묶어 피처 16개를 산출해 분석 DB에 적재하는 전 과정.
2. **손실 선별** — 초과손실 α(절대손익 − 동기간 KOSPI 수익률)로 시장 성분을 제거하고 복기 대상 손실만 선별.
3. **손실 원인 2분류** — 학습된 분류기가 손실 거래마다 진입오류·손절실패 두 점수(합 1)를 산출하고, 그 점수만으로 라우팅.
4. **총괄 상호작용** — 유형별 빈도·손실금액을 집계해 사용자에게 분석 관점을 질문하고, 선택에 따라 도메인 에이전트를 호출.
5. **도메인 에이전트 진단** — 진입오류·손절실패 각각의 근거(피처·손절선·이탈 시점·최대낙폭)로 거래별 원인 설명 생성.
6. **심리 신호 보강** — 리벤지 매매·처분효과·과매매를 계산해 진단 설명에 보강 신호로 부착(분류·라우팅에는 미반영).
7. **성향 리포트** — 반복 패턴을 사용자 프로파일 DB에 저장하고 코호트 비교와 교정 규칙을 카드로 제시.
8. **실시간 경고** — 보유 종목의 손절선 이탈 감지와 매수 예정 종목의 진입오류 위험 경고를, 위험도·근거와 함께 증권사 앱 목업 화면 위에 표시.
9. **생성형 AI 문장화** — 위 각 지점의 설명·질문·경고 문구를 LLM이 생성. LLM 미가용 시 룰 템플릿으로 자동 폴백하여 서비스가 중단되지 않음.
10. **아키텍처 실시간 추적** — 사용자가 진행하는 단계가 시스템의 어느 모듈인지 화면 우측 패널에서 실시간으로 점등.
11. **웹 서비스 배포** — 프론트엔드(Vercel)와 API 서버(Render) 분리 배포, 상시 접속 가능.

## 3. 사용자 이용 흐름

배포 URL 접속 후 순서는 다음과 같다. 각 단계에서 우측 아키텍처 패널이 해당 모듈을 자동으로 점등한다.

```
① 접속
   https://investment-loss-analysis.vercel.app
        ↓
② 체험 계정으로 둘러보기 클릭
   (별도 계정 발급·입력 불필요)
        ↓
③ 필수 동의 항목 체크 → 동의하고 시작하기
        ↓
④ [① 업로드] 예시 데이터셋 8명 중 1명 선택 → 내 거래 복기 시작하기
        ↓
⑤ [② 분석] 4단계 자동 진행 (약 10초)
   거래내역 파싱 → 초과손실 α 손실 선별 → 2-way 분류 → 거래별 설명 생성
   → 진단 결과 보기 클릭
        ↓
⑥ [③ 진단] 손실 유형 분포 확인
   빈도 1위와 금액 1위가 다르면 "무엇부터 볼지" 질문에 답 → 도메인 선택
        ↓
⑦ [④ 거래별] 손실 거래를 하나씩 넘겨보며
   원인 설명 · 분류 근거 피처 · 1분봉 복기 차트 확인
   (유형·심각도 필터로 좁혀 볼 수 있음)
        ↓
⑧ [⑤ 내 성향] 반복 패턴 카드와 교정 규칙 확인
        ↓
⑨ [⑥ 실시간 알림] 손절실패 시나리오 선택
   → 앱 목업 우상단 알림 벨 클릭
   → 손절 경고 카드(현재가·손절선·이탈 시점·위험도·근거) 확인
   (진입오류 시나리오가 있는 사용자는 토글로 전환 가능)
```

**우측 아키텍처 패널**은 보기 전용이다. 사용자가 왼쪽에서 단계를 진행하면 해당 모듈이 자동으로 점등되며, 상단의 `분석단`·`솔루션단` 버튼으로만 흐름을 바꿔 볼 수 있다. 화면 폭이 좁으면 상단 `아키텍처` 버튼으로 열고 닫는다.

## 4. AI 및 데이터 처리 방식

### 4-1. AI가 수행하는 역할

**(1) 학습 기반 분류기 — 손실 원인 2분류**

| 항목 | 내용 |
|---|---|
| 역할 | 청산된 손실 거래를 진입오류 / 손절실패로 분류 |
| 입력 | 사이클 전체경로 피처 16개 (진입맥락 13 + 사후경로 3) |
| 출력 | `entry_error_score`, `stop_loss_failure_score` (합 1), 라벨, 신뢰도 |
| 학습 데이터 | 실 KOSPI 1분봉 랜덤샘플 + 군집 라벨, n = 5,986 |
| 성능 | 5-fold CV AUC **0.839 ± 0.019** |
| 라벨 생성 | 손실 경로 2축(초반 손실 집중도, 최저점 도달 시점) GMM 군집(K=2), 실루엣 계수 0.48 |

라벨을 만든 두 축은 **학습 피처에서 제외**했다. 라벨 생성 신호를 설명에도 쓰면 자기참조가 생기기 때문이다.

**(2) 예측기 — 사전 경고**

| 모드 | 판단 시점 | 입력 | 출력 |
|---|---|---|---|
| `predict_entry_risk` | 매수하는 순간 | 진입맥락 피처(RSI·범위위치·추격도 등) | 위험도 점수, 경고 여부, 근거 목록 |
| `monitor_live_position` | 보유 중 급락 순간 | 현재 포지션(미실현손익, 손절선 이탈, 낙폭, 보유시간) | 위험도 점수, 경고 여부, 근거 목록 |

Random Forest(`n_estimators=120`, `max_depth=5`, `class_weight=balanced`) + 룰 스코어링 하이브리드. 학습 표본이 부족하면 룰 스코어러로 자동 전환되어 경고가 항상 생성된다. 두 모드 모두 **미래 정보를 사용하지 않는다.**

**(3) 생성형 AI(LLM) — 문장화 전담**

| 지점 | 입력 | 출력 |
|---|---|---|
| 거래별 원인 설명 | 분류 결과 + 근거 피처(JSON) | 2~3문장 원인 설명 |
| 총괄 상호작용 | 유형별 빈도·손실금 집계(JSON) | 분석 관점 질문 문장 |
| 성향 리포트 | 반복 패턴 + 코호트 비율(JSON) | 카드 제목·요약·교정 팁 |
| 실시간 경고 | 위험 신호(종목·손절선·미실현손익) | 1~2문장 경고 메시지 |

사용 모델은 **Qwen3-30B-A3B-Instruct**(오픈웨이트, OpenAI 호환 엔드포인트)이다.

**LLM에 적용한 제약**

- 입력 JSON에 없는 수치·종목·사실을 생성하지 못하도록 프롬프트에서 금지한다. 모든 숫자는 룰 엔진과 모델이 계산한 값이다.
- 분류·위험도 판정에 개입하지 않는다. 결과를 설명할 뿐이다.
- 매매 추천·미래 지시를 금지하고 사후 복기 톤을 유지한다.
- 호출 실패·키 부재·응답 이상 시 **룰 템플릿으로 자동 폴백**한다.

**(4) 룰·통계 엔진 — 심리 패턴 보강 신호**

| 패턴 | 판정 기준 | 근거 |
|---|---|---|
| 처분효과 | PGR − PLR ≥ 0.05 | Odean(1998) 실측 PGR 0.148 / PLR 0.098 |
| 과매매 | 연 회전율 + 월 거래빈도 개인 중앙값 대비 배수 | Barber & Odean(2000) |
| 리벤지 매매 | 직전 손실 후 임계시간 내 재진입 + 포지션 확대 + 재손실 | 행동재무 문헌 |

이 신호들은 **분류·라우팅에 가산하지 않는다.** 도메인 에이전트의 해석에만 사용한다.

### 4-2. 사용 데이터와 입력·출력

| 구분 | 내용 |
|---|---|
| **시세 데이터** | KOSPI 798종목 × 1년치 × 1분봉 = 5,467만 행 / 3.56GB (키움증권 REST API 수집, 2025-06-23 ~ 2026-06-23) |
| 제외 종목 | 우선주, ETN, ETF, SPAC, 상장폐지 종목 |
| **거래 데이터** | 체결 내역 (종목명, 거래량, 매수일시, 매도일시) |
| **입력** | 사용자 거래내역 + 해당 종목·기간의 1분봉 |
| **중간 산출** | 매수→매도 사이클, 초과손실 α, 피처 16개, 분류 점수, 심리 신호 |
| **출력** | 거래별 원인 진단, 유형별 집계, 성향 패턴, 실시간 위험 경고 |
| **저장소** | 분석 DB(사이클·피처·분석결과), 최종 DB(성향·반복패턴), 화면용 차트 캐시 |

**배포 환경 데이터**: 예시 데이터셋 8명이 실제로 참조하는 **134종목 분량(172MB)** 만 추출해 배포 서버에 탑재했다. 전체 1.1GB 대비 응답 속도와 배포 안정성을 확보하기 위한 조치이며, 화면에 표시되는 모든 값은 실제 수집된 1분봉에서 계산된다.

### 4-3. 개인정보 및 민감정보 처리

- **MVP는 실제 개인정보를 수집·저장하지 않는다.** 배포된 서비스는 사전에 준비된 예시 데이터셋 8명만 사용하며, 계정 생성·로그인·실계좌 연동이 없다.
- 예시 데이터셋의 사용자명은 식별 목적의 표시 라벨이며 실제 계좌·주민등록번호·연락처 등 어떤 개인식별정보도 포함하지 않는다.
- **LLM에 전송되는 데이터는 거래 통계 수치와 종목명뿐이다.** 계좌번호·성명·연락처 등 식별정보는 프롬프트에 포함되지 않는다.
- 동의 화면은 실서비스 전환 시 필요한 수집·이용 항목을 고지하는 UI로 구현되어 있으며, MVP 단계에서 실제 수집은 발생하지 않는다.
- 시세 데이터는 공개 시장 데이터이며 개인정보를 포함하지 않는다.

## 5. MVP 검증 방법

### 5-1. 심사자 확인 절차

**필요 계정: 없음.** 별도 발급·입력 없이 접속 즉시 전체 기능을 확인할 수 있다.

| 순서 | 조작 | 예상 결과 |
|---|---|---|
| 1 | https://investment-loss-analysis.vercel.app 접속 | "내 거래 복기를 이어서 확인해 볼까요?" 로그인 화면 표시 |

| 6 | 제시되는 질문에서 관점 하나 선택 | **빈도 1위는 손절실패, 금액 1위는 진입오류로 엇갈리는 케이스**라 시스템이 단정하지 않고 "무엇부터 보시겠습니까"를 질문한다. 선택한 도메인으로 ④ 거래별 화면 이동 |
| 7 | 거래 칩을 하나씩 클릭 | 종목별 1분봉 복기 차트(매수·손절선·손절 신호·청산 마커)와 원인 설명, 분류기 라우팅 점수 표시 |

| 12 | 상단 **아키텍처** 버튼 토글 | 우측 아키텍처 추적 패널 열림/닫힘. `/architecture` 단독 페이지로도 접근 가능 |

### 5-2. 샘플 입력값과 예상 결과

**입력은 데이터셋 선택뿐이며, 텍스트 입력이나 파일 업로드는 필요하지 않다.**

| 샘플 입력 (분석 대상) | 예상 결과 |
|---|---|
| **김민아** (권장) | 손실 7건. 손절실패 4건(9,965원) / 진입오류 3건(12,780원). **빈도 1위와 금액 1위가 엇갈려 총괄 상호작용 질문이 실제로 발생한다.** 성향 카드 "손절선 이탈 후 2일 이상 보유"(2건, 처분효과). 손절 경고와 **진입오류 경고 둘 다 확인 가능** |
| **안가은** | 손실 다수. 손절 경고와 진입오류 경고 둘 다 확인 가능 |
| 김지윤 / 김태희 / 방상운 / 오규원 / 장유경 / 정리나 | 손실 유형 분포와 성향 패턴 확인 가능. 실시간 알림은 손절실패 시나리오만 표시 |

> **김민아를 권장하는 이유**: 총괄 상호작용 질문(빈도 1위 ≠ 금액 1위)과 두 종류의 실시간 경고를 한 사용자에서 모두 확인할 수 있는 유일한 케이스다.
>
> **진입오류 시나리오는 김민아·안가은에서만 활성화된다.** 예시 데이터셋에서 매수 예정 종목이 있는 사용자에게만 해당 경고가 생성되기 때문이며, 두 시나리오를 모두 보시려면 **김민아**를 선택하시기를 권한다.

### 5-4. MVP 단계의 제한사항

정확한 심사를 위해 현재 단계에서 **동작하지 않는 부분**을 아래에 명시한다.

1. **실계좌 연동이 없다.** 증권사 계정 연결이나 실시간 잔고 조회는 포함되지 않으며, 사전에 준비된 예시 데이터셋으로 동작한다.
2. **CSV 파일 업로드 처리는 포함되지 않는다.** ① 업로드 화면은 실서비스의 진입 경험을 보여주는 UI이며, 실제 분석은 사전 분석된 예시 데이터셋을 선택하는 방식으로 진행된다.
3. **실시간 장중 스트리밍이 아니다.** 실시간 알림 화면은 수집된 1분봉을 특정 시점 기준으로 평가한 결과를 보여준다. 위험 판정 로직과 경고 생성은 실제로 동작하며, 시세 공급 경로만 배치 방식이다.
4. **배포 데이터는 134종목으로 한정했다.** 예시 데이터셋 8명이 실제 참조하는 종목만 탑재했다. 전체 798종목 분석 결과는 동일 코드로 재현 가능하다.
5. **인증·회원 기능이 없다.** 로그인 화면은 실서비스 진입 흐름을 보여주는 UI이며 실제 인증은 수행하지 않는다.
6. **예측기 성능은 데이터 축적에 따라 변한다.** 현재 실데이터 기준 AUC는 진입오류 0.51, 손절실패 0.68이다. 매수 시점에는 미래 정보가 없어 진입오류 예측의 상한이 구조적으로 낮으며, 실사용자 거래 로그가 쌓여야 임계값 보정과 성능 개선이 가능하다.
7. **생성형 AI 문장은 외부 API에 의존한다.** 다만 호출 실패 시 룰 템플릿으로 자동 폴백하므로 **어떤 경우에도 화면이 비거나 오류가 노출되지 않는다.**
