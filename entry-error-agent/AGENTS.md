# 개발 규칙

이 문서는 Codex가 앞으로 이 프로젝트를 수정할 때 지켜야 할 규칙입니다.

## 기본 원칙

- 초보자가 이해할 수 있도록 함수 중심으로 단순하게 작성한다.
- 복잡한 클래스 구조를 만들지 않는다.
- mock CSV 기준으로만 MVP를 개발한다.
- 로컬에서는 가벼운 구조 확인과 단위 수준 검증만 수행한다.
- 실제 대용량 데이터 처리는 이후 Colab 환경에서 수행할 수 있게 설계한다.

## 금지 사항

- `.venv` 가상환경을 생성하지 않는다.
- `pip install`을 실행하지 않는다.
- 대용량 데이터 파일을 생성하지 않는다.
- 실제 증권사 API에 연결하지 않는다.
- 머신러닝 모델을 사용하지 않는다.
- 손익 여부만으로 진입오류를 판정하지 않는다.
- 고점 매수를 무조건 오류로 판정하지 않는다.
- 진입 이후에 발생한 정보를 진입 당시 판단에 사용하지 않는다.

## 모듈 분리

- `data_loader.py`: 거래 CSV와 OHLCV CSV 로딩
- `schema_mapper.py`: 실제 CSV 컬럼명을 표준 컬럼명으로 변환
- `feature_engineering.py`: 진입 시점 기준 보조 지표와 맥락 피처 계산
- `entry_classifier.py`: 시장 상태 분류와 진입오류 라벨링
- `report_generator.py`: JSON 리포트와 자연어 복기 리포트 생성

## 분석 기준

- 손실 거래라고 해서 무조건 진입오류로 판정하지 않는다.
- 수익 거래라고 해서 좋은 진입으로 판정하지 않는다.
- 상승 돌파 매매와 단순 추격 매수를 구분한다.
- 하나의 거래는 여러 문제를 동시에 가질 수 있으므로 다중 라벨 구조를 사용한다.
- 데이터가 부족하면 억지 판정을 하지 않고 `analyzable=false` 또는 판단 보류 상태를 사용한다.
- 결과는 투자 조언이 아니라 사후 복기 리포트로 작성한다.
